# Architecture

This document describes the stable boundaries of the smolikja.team frontend.
It is organized by subsystem rather than as a catalog of every React component.

## Route families

| Public route | Implementation | Responsibility |
| --- | --- | --- |
| `/{locale}` | `src/app/[locale]/` | The localized landing page, its metadata and Open Graph image. Supported content URLs are always prefixed: `/cs` and `/en`. |
| `/` and any unprefixed path | `src/proxy.ts` | 307 redirect to the visitor's locale (cookie → `Accept-Language` → default). |
| unmatched `/{locale}/…` | `src/app/global-not-found.tsx` | Fully server-rendered, localized 404 with its own `<html lang>`. |
| `/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest`, `/icon.png`, `/apple-icon.png` | Metadata files in `src/app/` | Search-engine and install metadata generated by Next.js file conventions. |
| `/assets/*`, `/brand/*` | `public/` | Videos, screenshots, logo, PWA icons. Static; never redirected. |

`src/proxy.ts` applies locale redirects only to localizable page routes. The
metadata files, the Open Graph image route, framework internals, API paths and
anything with a file extension are excluded by its matcher. Keep `proxy.ts`
beside `src/app/`; this is the Next.js 16 file convention used by this project.

## Server and client boundaries

Server Components are the default. They load the dictionary, build metadata
and compose the page without shipping message catalogs or environment
variables to the browser.

Use a Client Component only when the subtree needs browser state, effects or
event handling. Current client islands:

| Island | Why it is client-side |
| --- | --- |
| `landing/hero-video.tsx` | Picks the video encode from viewport, DPR and `navigator.connection`; tracks playback readiness. |
| `landing/site-header.tsx` | Observes the hero with `IntersectionObserver` and slides the header in once it has scrolled away. |
| `landing/project-gallery.tsx` | Tracks scroll-edge state for the previous/next buttons. |
| `landing/contact-form.tsx` | `useActionState` around the contact Server Action. |
| `landing/reveal.tsx` | The single scroll reveal (statement section) via `motion`. |

Browser-only values are read through `useSyncExternalStore` with a server
snapshot, so the server renders a deterministic fallback and no state is set
inside an effect body. Values crossing from a Server Component to a Client
Component are serializable plain data; Server Actions are the supported
function exception.

Language switching is plain links (`layout/language-switcher.tsx`) — visiting
`/en` makes the proxy remember the choice in the `NEXT_LOCALE` cookie, so it
works without JavaScript.

Server-only integration code is marked explicitly:

- `src/app/actions/contact.ts` owns the contact mutation.
- `src/lib/contact-mail.ts` owns delivery through Resend.

Do not add an internal Route Handler merely to call it from a Server
Component. Read data directly in the Server Component layer and use Server
Actions for mutations initiated by this UI.

## Source ownership

| Location | Owns |
| --- | --- |
| `src/app/` | URL structure, layouts, page composition, metadata, the global 404 and Server Actions. |
| `src/components/landing/` | Landing-page sections and their composition (`landing-page.tsx`). |
| `src/components/layout/` | Shared layout helpers (language switcher). |
| `src/components/icons/` | Inline brand and third-party marks. |
| `src/components/ui/` | Generated shadcn primitives (Base UI + `cva`). Regenerate with the CLI; do not hand-edit their API. |
| `src/config/` | Locale-independent structural data: site URLs and links, navigation anchors, projects and screenshots, hero video encodes, brand assets. |
| `src/i18n/` | Locale types, language negotiation, dictionary loading and template formatting. |
| `src/lib/` | Shared server/domain utilities: fonts, `cn()`, video selection, rate limiting, mail delivery, OG rendering. |
| `messages/` | Localized user-facing copy. |
| `public/` | Static assets served from the site root. |
| `scripts/` | Repository tooling (`check-docs.mjs`). |

Prefer the narrowest existing subsystem. Create a new directory only when a
feature has a distinct responsibility and more than one collaborating module.

## Data flows

### Localized page

The locale segment is validated against `src/i18n/config.ts`. The page loads
the matching typed catalog, and `landing-page.tsx` passes only the dictionary
subtree each section renders. Structural values (project ids, screenshot
paths, links) come from `src/config/`, never from translation files;
`src/i18n/dictionaries.ts` cross-checks at load time that every configured
project and screenshot has copy.

### Hero video

`src/lib/video.ts` maps the physical viewport (CSS pixels × DPR, capped at 2)
and connection quality to one of four encodes in `src/config/video.ts`.
Data-saver and 2G-class connections get the inline wordmark only. The
wordmark is always rendered underneath the video as the JS-free fallback.

### Contact form

The client form invokes a Server Action. The action applies the honeypot,
process-local IP rate limiting and Zod validation, then hands the message to
the Resend delivery module. The browser never sees the API key. Details and
limitations in [Contact form](contact-form.md).

## Styling

Tailwind v4 with the shadcn `base-nova` preset. Semantic tokens are defined
once in `src/app/globals.css` as a single dark theme on true black (the hero
video's background); `<html class="dark">` is permanent so shadcn `dark:`
variants apply. Components use semantic utilities (`bg-card`,
`text-muted-foreground`, `bg-brand`) — never raw colours. `--brand` (Discord
blurple) is the only chromatic token and is reserved for the community CTA,
link hover and focus rings.

## Sources of truth

- User-facing copy: `messages/<locale>.json`, typed by `src/i18n/dictionary.ts`.
- Supported locales and URL behaviour: `src/i18n/config.ts` and `src/proxy.ts`.
- Site URL, e-mail, external links, navigation: `src/config/site.ts`.
- Projects, screenshots and their sizes: `src/config/projects.ts`.
- Hero video encodes: `src/config/video.ts`.
- Dependency versions and commands: `package.json`.
- Deployment commands: `nixpacks.toml` and `next.config.ts`.

Documentation should explain why these values matter and how systems
interact; it should link to the source rather than copying change-prone
values.
